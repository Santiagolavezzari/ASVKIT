Arquitectura del sistema

El sistema se compone de tres capas independientes que se comunican en cadena: los nodos sensores (emisor RF), la pulsera receptora (ESP32) y el backend web (Flask + SQLite).

RF 433 MHz
Pulsera

HTTP / Wi-Fi
Backend
Flask + SQLite
REST API
Panel web
HTML + JS (XAMPP)
Redundancia local: La comunicación RF entre nodo y pulsera es completamente offline. Aunque el Wi-Fi falle o el backend esté caído, la pulsera sigue recibiendo y mostrando alertas.

Comunicación inalámbrica

Protocolo RF 433 MHz

La señal RF usa modulación OOK (On-Off Keying) con la librería RCSwitch. Cada tipo de evento tiene un código numérico de 24 bits único, almacenado en la base de datos como rf_code.

Tipo de evento rf_code (ejemplo) Patrón vibración Ícono OLED
Timbre doorbell_A1 2 pulsos cortos BELL
Humo smoke_K3 Vibración continua SMOKE
Lavadora washer_M2 3 pulsos largos DONE
Puerta / Ventana door_window_P1 1 pulso medio DOOR
Rango RF: Con antena telescópica de 17.3 cm (λ/4 a 433 MHz), el alcance típico en interiores es de 20–50 m. Paredes de hormigón pueden reducirlo significativamente. Para plantas mayores se pueden agregar repetidores.
Arduino / ESP32

Firmware

El nodo sensor usa la librería RCSwitch para transmitir. El ESP32 de la pulsera usa RCSwitch para recibir y Adafruit SSD1306 para el display. La conexión al backend se realiza con HTTPClient.

Fragmento — Nodo sensor (Arduino)
// Envío de código RF al detectar el timbre #include <RCSwitch.h> RCSwitch mySwitch = RCSwitch(); void setup() { mySwitch.enableTransmit(10); // pin TX mySwitch.setProtocol(1); mySwitch.setPulseLength(320); pinMode(2, INPUT_PULLUP); // pin timbre } void loop() { if (digitalRead(2) == LOW) { mySwitch.send("doorbell_A1"); // código configurado en DB delay(500); // debounce } }
Fragmento — Pulsera ESP32 (receptor + POST al backend)
// Recepción y reporte al servidor if (mySwitch.available()) { String code = String(mySwitch.getReceivedValue()); mySwitch.resetAvailable(); // Mostrar en OLED y vibrar showAlert(code); vibrate(PATTERN_DOORBELL); // Reportar al backend Flask HTTPClient http; http.begin("http://192.168.1.X:5000/api/alerts"); http.addHeader("Content-Type", "application/json"); String body = "{\"rf_code\":\"" + code + "\"}"; int code = http.POST(body); http.end(); }
Servidor

Backend Flask

El servidor corre en Python con Flask, expone una API REST autenticada mediante sesiones HTTP, y persiste datos con SQLAlchemy sobre SQLite. Se ejecuta localmente en el mismo equipo que sirve el frontend.

Interfaz programática

API REST

Todos los endpoints retornan JSON. Los marcados con AUTH requieren sesión activa. Los marcados con ADMIN requieren rol admin.

POST
/api/auth/login
Autenticación con username + password. Retorna id, username, role. Implementa bloqueo tras 5 intentos fallidos.
POST
/api/auth/logout AUTH
Cierra la sesión del usuario autenticado.
GET
/api/auth/me AUTH
Retorna el perfil del usuario actual.
POST
/api/auth/change-password AUTH
Cambia la contraseña validando la actual. Mínimo 8 caracteres.
GET
/api/stats AUTH
Retorna contadores: alertas hoy, sensores activos/total, última alerta.
GET
/api/stats/chart AUTH
Serie temporal de alertas por día (últimos N días, configurable).
GET
/api/alerts AUTH
Listado paginado de alertas. Soporta filtros: ?type=, ?rf=, ?push=, ?page=, ?per_page=
POST
/api/alerts
Crea una alerta. El ESP32 llama a este endpoint con {rf_code}. No requiere sesión (endpoint de hardware).
GET
/api/sensors AUTH
Lista todos los nodos sensores registrados.
POST
/api/sensors AUTH
Registra un nuevo nodo sensor con name, type, rf_code, location.
PUT
/api/sensors/:id AUTH
Actualiza nombre, ubicación o estado activo de un sensor.
DELETE
/api/sensors/:id AUTH ADMIN
Elimina un sensor. Solo administradores.
GET
/api/users AUTH ADMIN
Lista usuarios con estado de bloqueo. Solo administradores.
PUT
/api/users/:id AUTH ADMIN
Actualiza rol, estado activo o desbloquea cuenta (unlock: true).
Autenticación y protección

Seguridad

El sistema implementa varias capas de seguridad orientadas a un despliegue en red local.

Contraseñas
Hash bcrypt
Las contraseñas se almacenan con hash bcrypt via werkzeug.security. Nunca en texto plano.
Brute-force
Bloqueo de cuenta
Tras 5 intentos fallidos consecutivos, la cuenta se bloquea automáticamente por 15 minutos. El admin puede desbloquear manualmente.
Sesión
Cookie segura
SESSION_COOKIE_SAMESITE=Lax evita CSRF de terceros. flask-login gestiona la sesión del servidor.
CORS
Orígenes permitidos
Flask-CORS limita las peticiones a localhost, 127.0.0.1 y null (file://). No se aceptan orígenes externos.
